# Domain Docs

工程技能在探索本仓库时应如何消费领域文档。

## 阅读顺序

- 优先读取仓库根目录的 **`CONTEXT.md`**（如果存在）。
- 如果根目录存在 **`CONTEXT-MAP.md`**，则按其中指向读取各上下文的 `CONTEXT.md`。
- 查看 **`docs/adr/`** 中与当前工作区域相关的 ADR。

若上述文件不存在，**静默继续**，不要主动建议创建。术语与架构决策由 `/grill-with-docs` 等技能在需要时惰性生成。

## 文件结构

本项目为单上下文仓库（single-context）：

```
/
├── CONTEXT.md          ← 项目领域术语表与业务上下文（待创建）
├── docs/adr/           ← 架构决策记录（待建立）
├── .impeccable.md      ← 设计上下文（品牌个性、美学方向、设计原则）
└── src/
```

## 使用术语表词汇

当输出涉及领域概念（issue 标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中定义的术语。若概念尚未出现在术语表中，需判断是项目未使用的语言还是真实缺口；后者可记录到 `/grill-with-docs`。

## 标记 ADR 冲突

若输出与现有 ADR 冲突，应显式指出，而非静默覆盖：

> _与 ADR-XXXX 冲突——但值得重新讨论，因为……_
